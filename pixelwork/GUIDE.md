# 像素帧动画生成方法说明（Pillow 手工绘制法）

## 1. 图片到底是怎么生成的

**不是 AI 画图，不是扩散模型，是「程序化点阵绘制」。** 全流程三层：

```
① 设计层（Agent 决定造型与姿态参数）
        ↓
② 绘制层（Python + Pillow，用矩形/椭圆/多边形/线段在 64×64 网格上画颜色索引）
        ↓
③ 导出层（合成图层 → 编码 RGBA PNG → 拼精灵表 → 计算 SHA256 校验）
```

关键点：**每一帧都是真实逐个像素画出来的**，不是复制粘贴换名字。人物不是"一张图切 20 块"，而是同一个角色模型在不同姿态参数下重新绘制 20 次。

## 2. 用 py 脚本能直接做图吗？能

只需要 **Pillow**（本仓库用 12.3.0，在隔离 venv：
`C:\Users\PC-7020\.workbuddy\binaries\python\envs\default\Scripts\python.exe`）。

最小示例：

```python
from PIL import Image, ImageDraw
im = Image.new('P', (64, 64), 0)          # 'P' = 调色板索引模式
d  = ImageDraw.Draw(im)
d.rectangle((10, 10, 30, 40), fill=8)    # fill=8 表示第 8 号颜色，不是 RGB
im.putpalette(...)                        # 或自己合成 RGBA 输出
```

用 `'P'` 模式（索引色）而不是 `'RGB'` 的好处：
- 天然保证"有限配色"，不会出现几百种杂色（像素画的大忌）
- 改色只需改调色板，或改索引矩阵
- 图层可以独立存成二维索引矩阵，便于后续精确修订某一块

## 3. 人物是怎么画出来的（本项目实际做法）

角色拆成 **4 个图层**，自下而上合成：

| 图层 | 内容 | 为什么要分层 |
|---|---|---|
| `hair` | 脑后长发 | 在身体后面，且要独立摆动 |
| `body` | 头/帽子/躯干/手臂/腿/鞋 | 主体 |
| `bow` | 武器 + 弓弦 + 箭 | 在身体前面，且要独立运动 |
| `fx` | 特效（闪光、斩击、残影、尘土） | 最上层，可整层开关 |

**姿态 = 参数，不是重画**。同一套绘制函数吃不同参数：

```python
frame_layers('jump_2', dy=-7, legs=3, hair=-2)   # 空中收腿：整体上移7px、收腿、头发后飘
frame_layers('walk_1', dy=0,  legs=0, hair=0 )   # 行走中立帧
```

参数含义：`dy` 整体上下位移、`lean` 身体前倾、`legs` 腿部姿态枚举（并立/左前/右前/收拢/大跨）、
`hair` 发梢摆动像素、`draw_px` 弓弦拉开量、`arrow` 箭的状态（搭箭/飞行）、`fx_fn` 特效。

这样 20 帧只需要 5 个动作 × 4 帧的姿态参数表，改动作只需改参数，不动造型代码。

## 4. 有哪些硬性约定（像素画规范）

这些约定决定成品像不像"像素画"，务必遵守：

1. **有限调色板**：16 色上限（本项目 16 色，含 0 号透明）。多了就不像素了。
2. **索引 0 必须是透明**：`(0,0,0,0)`，其余颜色必须完全不透明（alpha=255）。
3. **画布必须是 16/32/64 正方形**（工程校验器强制）。
4. **只用硬边**：`Image.Resampling.NEAREST` 放大，**绝不做抗锯齿/模糊/羽化**。
5. **透明底**：每帧都是带 alpha 的 RGBA PNG，方便直接铺到游戏场景。
6. **有描边**：主色块外一圈深色（索引 1），轮廓才清晰。
7. **关键锚点固定**：头、腰、脚的基准坐标写死，姿态只做相对偏移——否则帧之间人物会"抖动/漂移"。
8. **单工程帧数上限 8 帧**（校验器限制），所以 20 帧拆成 3 个同源工程包。
9. **帧间要有真实差异**：校验器会拒绝"所有帧渲染结果相同"的工程（`IDENTICAL_POSES`）。
10. **出图后必须人工看图**：机械校验通过 ≠ 好看。本项目第一版就是靠放大目检才发现"绿瞳被描边吃成黑块""持弓手悬空"两个问题。

## 5. 想让其他 Agent 也能生成帧动画，怎么做

三条路，由轻到重：

### 方案 A：给它一段"做法说明书"（最快）
把本目录下的 `frame_anim_template.py` 作为骨架 + 本文的约定清单，
在派发任务时写进 prompt：**"按这个模板，把 draw_xxx 换成你的角色，填 ACTIONS 姿态表，运行脚本出图"**。

### 方案 B：封装成 Skill（推荐，一次投入长期复用）
在 `~/.workbuddy/skills/pixel-frame-animator/` 下建 `SKILL.md`，内容包含：
- 何时触发（用户要"帧动画/行走攻击跳跃/像素角色"）
- 必须遵守的 10 条约定（上文第 4 节）
- 调用模板脚本的标准流程
- 交付物清单 + 人工目检要求

之后任何 Agent 会话只要触发该 Skill，就会按同一套规范出图，风格和质量可保持一致。
**需要我帮你把它正式封装成 Skill 的话，说一声即可。**

### 方案 C：做成 MCP 工具/命令行
把模板脚本包装成 `pixelanim --character xxx.json --out dir`，其他 Agent 直接调用命令。
适合要批量、要给非 Python 环境用的场景。

## 6. 本次交付的复核流程（可复用）

```
check  → 校验工程合法性（零写入，纯内存绘制核验）
build  → 生成新目录交付包（绝不覆盖旧成果）
verify → 用包外独立保存的 manifest SHA256 复核包完整性
目检   → 真实打开 8x 联系表逐帧判断轮廓/姿态差异/部位一致/不截断
```

要让我（或任何 Agent）改某一帧的某个部位，正确做法是：
**先读旧工程 + 提供 SHA → 生成 revision+1 的新工程 → 限定矩形区域修改 → 新旧对照 → 保留旧包**，
而不是直接覆盖原图。
